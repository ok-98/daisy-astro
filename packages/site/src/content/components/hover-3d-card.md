`Hover3dCard` wraps a single element and tilts it toward the mouse, with a soft shine that follows the
pointer. Pass **exactly one child** — it becomes the card. The tilt zones are generated by the
component itself, so there is nothing else to render inside.

## Props

| Prop | Type | Notes |
|---|---|---|
| — | — | No props beyond native `<div>` attributes. The tilt effect has no configurable axis. |

Every native `<div>` attribute forwards (`id`, `class`, `data-*`, `style`, event handlers, ...).

## Pass exactly one element

Internally, eight invisible hover zones are rendered after your content to drive the tilt. If you pass
a second top-level element, it gets mistaken for one of those zones — it picks up a stray scale and
grid position, and the tilt map shifts by one. Always wrap multiple things (an image plus a caption,
say) in a single container element first.

## The shine needs something that can clip

The shine is a pseudo-element on your card, clipped by the card's own `overflow: hidden`. A bare
`<img>` tilts correctly but never shines, because an `<img>` can't have a pseudo-element. Wrap an image
in a `<div>` (or use `Card`) when the shine matters.

## No middle zone, on purpose

The pointer grid deliberately has no centre cell, so the card returns flat whenever the pointer is over
the middle — that's what makes the tilt read as physical rather than snapping between fixed positions.
